## Context

v1.7.3 按 pstack G1 反哺生成 `verify-md-bundle` 静态验证技能并完成端到端自证。随后在功能迭代语境下评估其成立性，发现三条结构性问题（静态文档腐烂、触发条件不满足、平行结构漂移，详见 proposal「Why」）。本设计记录撤销决策与替代方案。

**约束**：
- 约定必须落进既有受管文件（SKILL.md 编排层 + evidence-capture.md 规范层），不新增受管文件
- 保持模板硬规则（首行模板头 / 结尾换行 / 无仓库特有值——CI 禁串含 `pnpm`、`apps/web` 等）
- 本仓纪律：先红后绿（e2e 先加断言、确认红、再改到绿）

## Goals / Non-Goals

**Goals:**
- 撤销静态技能副本，消除其腐烂与漂移风险
- 把稳定的探针形态约定落进既有规范（活代码优先）
- e2e 断言守住约定存在与无残留

**Non-Goals:**
- 不删除 pstack 反哺的其他成果（P0 四件套、验证分离、overlap 预检均保留）
- 不为其他仓生成任何 verify-* 技能
- 不改 QG-5/DQ-3/DQ-5 的门禁判据本身（只加「探针形态」这一层）

## Decisions

### 决策 1：撤销而非维护

**选择**：删除 verify-md-bundle；不引入 pstack 的 `/maintain-verification-skill` 维护循环。

**理由**：维护循环成本高（每次全特性实跑 + 修正 PR），而收益场景（无脚本化验证路径）在消费仓均不存在。在「活代码 e2e 已覆盖」的现实下，静态副本 + 维护循环是双重成本。

**备选**：保留技能 + 实现维护循环 — 拒绝，为不存在的需求付费。

### 决策 2：约定落两层（编排层 + 规范层）

**选择**：SKILL.md G1 出口写条款（选哪种形态）；evidence-capture.md 写规范（四段式：规则/理由/实证案例/如何验证）。

**理由**：与既有分工一致——SKILL.md 管编排（gate 引用规范），evidence-capture.md 管证据采集细则。单一事实来源不重复。

### 决策 3：插入新节导致编号顺延

**选择**：evidence-capture.md 在「三、5 类证据规范」后插入「四、探针形态（活代码优先）」，原四/五/六顺延为五/六/七；同步 §五→§六 跨节引用一处 + 引言一句。

**理由**：避免触动「三、5 类证据规范」的 3.x 子节编号（5 个子节标题 + 内部引用），改动面减半；逻辑序（何时采 → 采什么 → 用什么形态写探针 → 挂载点）仍然成立；本仓已有「旧 §八 顺延 §九」先例。

## Risks / Trade-offs

- **[每票写探针的自觉性]** → 约定只能约束形态，不能强制探针质量；由 QG-5 原始证据判据兜底（未附证据不予采信）
- **[纯库仓无 e2e 基建]** → 降级路径（轻量探针 + evidence-capture 约定）覆盖；不强迫建基建
- **[消费仓升级后的旧引用]** → SKILL.md 是受管文件，升级自动替换；无需手工清理

## Migration Plan

1. 删除消费仓试点产物
2. e2e 先红（+3 断言）
3. SKILL.md + evidence-capture.md 修订 → e2e 绿
4. VERSION/CHANGELOG/config 对齐 → rollout 4 仓验证
5. 归档 change
